Read-only (evaluation) mode

Settings > Accounts · Castellum

Every account you add to Castellum starts in read-only (evaluation) mode. Castellum downloads and shows your mail, but makes no changes on the mail server. This is deliberate: you can try the app on a real mailbox with nothing at risk, and switch writes on only when you are ready.

1. What read-only means

While an account is read-only, these actions are refused for it: archiving, deleting, flagging, marking read or unread, and sending. If you try one, Castellum shows a “This Account Is Read-only” dialog that says the action was not applied and offers Enable Writes or Keep Read-only. If the action was Send from a compose window, Castellum repeats it for you straight after you enable writes.

Why does Archive seem to do nothing? If an account has just been added, this is the reason. Nothing is wrong with the account; it simply has not had writes enabled yet.

Other things that change the server also wait: rules cannot change mail on a read-only account, and tags need writes too, because they are stored on the server as IMAP keywords.

2. Seeing the state

Open Settings > Accounts. Each account row has a button on its right: Enable Writes… if the account is read-only, or Return to Read-only… if writes are on. Hover over it for a one-line explanation. Under the list, a footer reads “N of M accounts read-only (evaluation mode).” or “Writes are enabled for every account.”

If Castellum has not yet heard back about an account, it shows it as read-only. It never shows an account as writable unless that is confirmed.

3. Enabling writes

  1. For one account, click Enable Writes… on its row.
  2. For every read-only account at once, click Enable Writes for All Accounts… in the footer. The confirmation lists each account it covers.
  3. Read the confirmation and click Enable Writes (or Enable Writes for All). Nothing changes until you do.

Enabling for all covers only the accounts listed. An account you add later still starts read-only.

4. Going back

Click Return to Read-only… on the account row and confirm. The account stops making changes on the server. Changes still queued for it are not sent while it stays read-only, and archiving, deleting, flagging and sending are refused again. Nothing already done on the server is undone.
